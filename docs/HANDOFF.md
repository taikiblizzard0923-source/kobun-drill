# 日ごとの問題ドリル（汎用版）開発 指示メモ

TEAP 19日ドリル（https://taikiblizzard0923-source.github.io/teap-drill/ ）を土台に、
**別の試験・科目でも使い回せる「日ごとの問題ドリル」**を作るための引き継ぎメモ。
新しいチャットではまずこのメモを読み、最後の「最初にやること」から始めること。

---

## 1. ゴール

- 試験名・試験日・学習者のレベル・1日の学習時間を入力すると、**試験日までの日別ドリル**（やること・語彙・予想問題・解説・音声）を作れるようにする。
- 出力は**静的サイト**（index.html + data/*.js + audio/*.mp3）。GitHub Pages に置き、iPad の Safari で使う。
- TEAP 版で作った仕組み（下記）を「エンジン」と「試験ごとのデータ」に分け、データの差し替えだけで別の試験に流用できるようにする。

## 2. 現在の TEAP 版の構成（リポジトリ `taikiblizzard0923-source/teap-drill`）

```
index.html        画面とロジック一式（CSS・JS インライン、ライブラリなし）
data/d1103.js     日別データ（window.TEAP.days["YYYY-MM-DD"] = {...}）
data/w1.js w2.js mocks.js w3.js   同上（週・模試ごとに分割）
data/audio.js     window.TEAP_AUDIO = { "日付|セットid[|問題idx]": "audio/xxx.mp3" }
data/must.js      window.TEAP_MUST  = { "日付|セットid|問題idx": "★の理由" }
audio/*.mp3       ニューラル音声（96本・約25MB）
docs/SPEC.md      データ形式の仕様（Day / Set / Item）
docs/REVISE.md    公式見本に合わせたレベル・形式の修正指示
docs/EXPLAIN.md   詳しい解説・全訳の書き方の指示
tools/gen.py      Kokoro TTS で MP3 を生成
tools/check.js    構文・4択・正解位置の偏り・tasks合計分数の検査
tools/verify_ex.js 解説追加の前後で問題文/選択肢/正解/スクリプトが変わっていないかの検査
tools/dup.js      語彙の重複チェック
tools/e2e.js      Playwright で全日表示＋全セット答え合わせ（iPad横・縦・スマホ）
```

### 画面の機能（流用時もそのまま残す）
- 日付の帯（今日を強調、正答率、完了マーク）、本番までの残り日数
- 日ごとに：テーマ／「今日は〇〇の日」＋応援メッセージ／やること（チェックボックス・分数）／語彙（タップで意味）／問題セット
- 問題：マークシート風の4択、タイマー、答え合わせ、正答率、解き直し
- 解説：【正解】【根拠 or 文の訳】【他の選択肢】【ポイント】を見出し付きで表示、全訳・スクリプト和訳は答え合わせ後に表示
- ★落とせない問題の印と「★ x/y 正解」表示
- 音声：`<audio controls>`。**fetch → Blob → objectURL で再生**（iPad Safari 対策、後述）。失敗時は speechSynthesis にフォールバック
- iPad 最適化：900px 以上で「本文・図表・音声は左に固定、問題は右」の2カラム、文字・タップ領域を大きく
- 記録は localStorage（端末ごと）。読み書きはすべて try/catch
- テーマ：白×桜色（ライト／ダーク両対応、トークンは :root に定義）

## 3. 汎用化でやること

1. **設定ファイルを1つにまとめる**（例 `data/config.js`）
   - 試験名・試験日・開始日、ブランド色、日付ごとの「〇〇の日」名・応援メッセージ、攻略メモ（試験構成表・コツ）、スキル名（R/L 以外にも対応：例「文法」「計算」など）
   - 今 index.html に直書きしている `EXAM` 日付・`PLAN`・`OSHI`・`CHEER`・攻略メモ HTML・タイトルを config に移す
2. **名前空間を汎用化**：`window.TEAP` → `window.DRILL`（互換のため TEAP も読めるようにしてよい）。localStorage キーも試験ごとに分ける（`drill-<試験ID>-v1`）
3. **スキル種別の一般化**：今は `skill: "R" | "L"`。任意のタグ（色・ラベル）を config で定義できるようにする。音声付きセットは `script` の有無で判定（今と同じ）
4. **生成パイプラインをスクリプト化**（下の §4 を1コマンドずつ実行できる形に）
5. **README に「新しい試験を作る手順」**を書く

## 4. 問題データの作り方（TEAP で実際にうまくいった手順）

1. **公式の構成・見本問題を必ず確認**してからレベルを決める（TEAP では当初、文法問題を入れてしまい、公式見本と照合して作り直した）。公式見本の本文はコピーせず、レベル・形式の確認だけに使う
2. **仕様書（SPEC.md 相当）を先に書き**、日ごと・週ごとにサブエージェントへ並列で生成させる（1エージェント = 1ファイル。同じファイルを2つのエージェントに触らせない）
3. 各ファイルを `check.js` で検査（構文、4択、正解位置 0〜3 の偏り、tasks の分数合計 = minutes、vocab 25語）
4. **解説・和訳の追加は別工程**（EXPLAIN.md）。前後で `verify_ex.js` を通し、問題文・選択肢・正解・スクリプトが1文字も変わっていないことを確認（音声と問題番号がひもづいているため）
5. **★落とせない問題**は別エージェントが全問を読んで判定し、`must.js` に出力（全体の約6割。基準は「本文にほぼそのまま答えがある／基本語」）
6. **ブラインド検証**：正解・解説を伏せた問題集を作り、別エージェントに解かせて正解キーと照合。不一致と「曖昧／誤答肢が実は正しい／英語の不自然さ」の指摘を人が見て修正（TEAP では 366問中 一致366、要修正4問）
7. `e2e.js` で全日表示・全セット答え合わせ・横スクロールなし・JS エラーなしを確認

## 5. 音声の作り方

- **Kokoro TTS（kokoro-onnx, int8 モデル）**：PyPI と GitHub Releases から取得できた（Hugging Face はこの環境から不可）
  - モデル：`kokoro-v1.0.int8.onnx` / `voices-v1.0.bin`（GitHub: thewh1teagle/kokoro-onnx の Releases `model-files-v1.0`）
  - 声：W=af_heart, W2=af_bella, M=am_michael, M2=am_puck, 講義(N)は am_michael/af_heart/bm_george/bf_emma からキーのハッシュで選択、Situation・Question の読み上げは af_sarah
  - 速さ：**speed=0.92、話者交代の間 0.45 秒、Situation 後 0.8 秒、Question 前 1.0 秒** → 約149語/分（TEAP 公式見本は約142語/分）。試験が変わったら公式音源で語/分を測って合わせる
  - 1A/1B のような短い問題は最後に "Question: …" を読み上げる
  - ffmpeg で MP3 48kbps モノラル。生成速度は実時間の約0.27倍（CPU 4コア）
- `tools/gen.py` は `scripts.json`（キー＋行の配列）を読み、`audio/*.mp3` と `data/audio.js` を出す。スクリプト文を変えたら該当キーの MP3 を作り直すこと

## 6. ハマりどころ（必ず守る）

- **claude.ai の Artifact は iPadOS 26 未満で開けない**（"This browser isn't supported / Update iPadOS"）。iPad 向けは最初から GitHub Pages で出す
- **iPad Safari は Range 非対応のサーバーから音声をストリーム再生できない**。音声は fetch で丸ごと読み込み Blob URL で再生する（GitHub Pages は Range 対応だが、念のため Blob 方式を維持）
- 祖先要素に `overflow:hidden` があると `position:sticky` が効かない（2カラムの左固定が壊れる）
- 実在の人物（アイドル等）の名前は「今日は〇〇の日」のラベルまでにする。**本人の発言に見える応援メッセージは作らない**（メッセージはページからの言葉として書く）
- 公開サイトに学習者の本名・呼び名を入れない（TEAP 公開版では「あかりん」を削除済み）
- 学習時間は日ごとに変わる（TEAP では 11/3・11/15 を90分、土日の一部を3時間に変更）。`minutes` と `tasks[].min` の合計を必ず一致させる
- 正解の位置は 0〜3 に均等に散らす。誤答肢は本文の語を使ったもっともらしいものに
- 公式の見本問題・過去問の文章や設問はコピーしない（オリジナルのみ）

## 7. 新しいチャットで最初にやること

1. このリポジトリ（`taikiblizzard0923-source/teap-drill`）を読み、index.html と docs/ を把握する
2. ユーザーに確認（選択肢付きで）：
   - 対象の試験・科目名、試験日、学習者のレベル（例：英検2級A）、目標
   - 平日・休日の学習時間、時間が取れない日
   - 公開先（GitHub Pages の新リポジトリ名）と、公開ページに入れてよい個人情報
   - 「〇〇の日」のテーマにする人・キャラクター（任意）
3. 公式サイトで試験構成・見本問題を確認（必要ならネットワーク許可をユーザーに依頼）
4. エンジン（index.html）を config 化 → TEAP のデータで動作確認（e2e.js）→ 新しい試験のデータを §4 の手順で生成
5. 報告は簡潔に、選択肢は番号付きで（ユーザーはスマホ／iPad から操作）

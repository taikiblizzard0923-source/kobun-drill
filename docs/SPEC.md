# MARCH古文 予想問題データ仕様

学習者：高校3年生。共通テスト古文で7〜8割取れる。基礎文法・基本単語は一通り終わっている。目標は MARCH（明治・青山学院・立教・中央・法政）一般入試の古文で7割以上。
学習時間：平日30分・土日60分。期間 2026-11-16（月）〜 2026-12-13（日）の28日。

## 大原則
- 問題・解説・現代語訳はすべてオリジナル。**大学入試の過去問・市販問題集の設問や解説をコピーしない**。
- 本文は著作権の切れた古典作品から取ってよい。ただし**原文を正確に覚えている箇所だけ**を使う。記憶があいまいなら、その作品の文体に倣ったオリジナルの擬古文にする。どちらの場合も本文の最後の段落に出典を書く：
  - 原文ベース：`（出典：『宇治拾遺物語』巻一による。一部改変）`
  - 擬古文：`（出典：『宇治拾遺物語』の文体による擬古文）`
- 古文として文法的に正しいこと（係り結び、活用、敬語の向き）。擬古文でも平安・中世の文法規範どおりに書く。
- 設問は**本文・例文だけを根拠に答えが1つに決まる**こと。誤答肢が「実は正しい」と言えないか必ず確認。
- 難易度は MARCH 標準〜やや難。基本で解ける問題（★候補）を約6割、思考を要する問題を約4割。
- 正解の位置（a = 0〜3）は各日・各ファイルで偏らないように散らす。誤答肢は本文の語を使ったもっともらしいものにし、選択肢の長さをそろえる。

## ファイル形式
1日1ファイル：`data/days/YYYY-MM-DD.js`。素の JavaScript。冒頭は必ず：

```js
window.DRILL = window.DRILL || { days: {} };
DRILL.days["2026-11-16"] = { ... };
```
テンプレートリテラル（バッククォート）は使わない。文字列中の `"` と `\` はエスケープ。改行は `\n`。

## Day
```js
{
  theme: "助動詞①（推量・意志）",   // config の plan と同じ趣旨で短く
  minutes: 30,                        // 平日30・土日60
  tasks: [ { min: 5, text: "…" }, … ], // 3〜6個。min の合計 = minutes（必ず一致）
  vocab: [ ["あはれなり","しみじみと心を動かされる・趣深い"], … ], // 15語。[古語（終止形・ひらがな中心）, 主な意味]。担当範囲は依頼文に従う
  sets: [ Set, … ]
}
```
tasks は具体的に（例：「単語：15語を古語→意味で言えるまで（5分）」「セットA：8問を6分で解き、答え合わせ」「セットB：本文→設問。終わったら現代語訳で読み違いを確認」）。

## Set
```js
{
  id: "A",                  // 日内で一意（A, B, M1, M2 など）
  skill: "G" | "R" | "M",   // G=文法・語彙の小問、R=読解、M=模試
  title: "文法：助動詞の意味",
  limitMin: 6,
  directions: "傍線部の文法的説明として最も適切なものを選びなさい。",
  passage: "古文本文…",      // R・M のみ。段落は \n\n。傍線は [[1|傍線部]]、空欄は（ X ）。最後の段落は出典、注があれば出典の前に「（注）…」段落
  passageJa: "現代語訳…",    // passage があれば必須。全文の自然な現代語訳（段落対応）。出典段落と注は訳さない
  items: [ Item, … ]
}
```

## Item
```js
{
  q: "傍線部1「見えぬ」の「ぬ」の文法的説明として最も適切なものを選べ。",
  choices: ["…","…","…","…"],  // 必ず4つ
  a: 2,                         // 正解 index（0〜3）
  ex: "【正解】3 打消の助動詞「ず」の連体形\n【根拠】本文「京には見えぬ鳥なれば」（＝都では見かけない鳥なので）。未然形「見え」に接続し、体言「鳥」に続くので連体形。\n【他の選択肢】1 完了「ぬ」の終止形：連用形接続なので不可／2 …／4 …\n【ポイント】「ぬ」の識別は直前の活用形（未然→打消、連用→完了）。"
}
```
- ex は必ず4見出し：【正解】【根拠】（G の小問は【文の訳】でもよい）【他の選択肢】【ポイント】。150〜300字。番号は 1〜4（index+1）。他の選択肢は3つすべて、なぜ違うかを書く。
- G の小問は q の中に短い古文の例文を入れる（例：`次の傍線部の「なり」の説明として適切なものを選べ。\n「秋の夜の月は、ことにあはれ__なり__。」`）。下線は `__…__`。例文は有名な古典の一節かオリジナル。
- R の設問は MARCH 型：語句の意味／傍線部の現代語訳／文法（識別・敬語の種類と方向）／主語・指示内容／和歌の修辞・解釈／心情・理由／内容一致／文学史（ジャンル・成立時代・同時代の作品）。

## 日ごとの型
- **平日（30分）**：セットA（G）8問・limitMin 6 ＋ セットB（R）本文400〜700字・5問・limitMin 12。
- **土日（60分）**：セットA（G）8問・limitMin 6 ＋ セットB（R）本文900〜1400字・8問・limitMin 25。
- **模試日（12/5・12/12、60分）**：セットM1（M）本文1200〜1600字・12問・limitMin 30（文法・単語・現代語訳・主語・和歌・心情・内容一致・文学史をすべて含む）＋ セットM2（G）8問・limitMin 8。
- その日のテーマ（文法項目・読解技術）を A と B の両方に反映させる。B の本文は config の label の作品・作者から取る（下の表）。

## 検査
完了後に必ず実行し、OK になるまで直す：
`node tools/check.js data/days/<担当の日付>.js …`
（構文、4択、a の範囲、正解位置の偏り、tasks 合計 = minutes、vocab 15語、ex の4見出し、passageJa の有無）

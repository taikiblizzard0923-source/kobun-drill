# 過去問形式ドリル（2026-12-14〜2027-02-21）データ仕様

まず docs/SPEC.md（基本仕様：オリジナル性、出典の書き方、文法の正しさ、解説の4見出し、ファイル形式）を読むこと。ここではその**差分と大学別の型**を定める。
根拠の調査メモ：docs/research/kyotsu.md, meiji_chuo.md, rikkyo_hosei_gakushuin.md, waseda.md（担当の型の章は必ず読む）。
日程表：docs/schedule2.json（日付ごとの型・分数・本番日かどうか）。

## 絶対ルール（SPEC.md に加えて）
- **過去問の本文・設問・選択肢を使わない**。調査メモに載っている過去の出典作品名・章段は避け、別の作品や別の箇所を使う。
- 本文は古典の原文（確実に覚えている箇所のみ、一部改変可）か、作品の文体に倣った擬古文。出典段落に必ず明記。私大型は「なじみの薄い作品」が多いので、擬古文で中世・近世の作品風に書いてよい（例：『〇〇物語』（架空ではなく実在の作品名に「の文体による擬古文」と添える））。
- 同じ担当内・他担当と本文の作品が偏らないよう、担当表の作品候補から選ぶ。

## Day（SPEC.md からの変更点）
- `vocab`: **新出3語だけ**（残り12語は画面が過去の日から自動で復習出題する）。担当の五十音範囲から、docs/vocab_used.txt にない語（連語・慣用句・難語も可）を選ぶ。その日の本文に出てくる語が望ましい。
- `cheer`: その日の応援メッセージ（40〜70字、ページからの言葉。実在の人物の発言にしない）。本番日は「今日は本番。…」から始め、夜の確認は軽くてよいと伝える。
- `minutes` と `tasks`：schedule2.json の minutes に合わせ、tasks の合計を一致させる。本番日（exam:true）は30分で「本番お疲れさま。余裕があれば翌日の形式を15分だけ確認」など軽い内容にする。
- `theme`: 例「立教型：中古の物語（和歌あり）」。

## Set の共通
- 1つの型 = 1セット（`id` は "A","B"）。G（弱点小問）は SPEC.md の G と同じ8問・6分。
- `skill` に型のキー（KY, MZ, MH, CH, CK, RK, HS, GK, WH, WS, G）を入れる。`title` は「立教型：『〇〇』」のように。
- `directions` は本番風の日本語指示（リード文を含めてよい）。
- `nChoices`: そのセットの基本の選択肢数（4 か 5）。本文合致の「合致／不合致」は2択の item にしてよい。
- `labels`: 選択肢の記号。早稲田型は "iroha"（イ〜ホ）、明治全学部型は "abc"（A〜D）、それ以外は省略（1〜5）。ex の【正解】もその記号で書く（例【正解】ハ …）。
- 記述問題は item を `{ type: "write", q: "…（10字以内）", ans: "解答例", ex: "【採点基準】…\n【ポイント】…" }`。答え合わせ後に解答例が出て、学習者が自分で○×をつける。
- 正解位置は選択肢数の範囲で均等に散らす（5択なら0〜4）。
